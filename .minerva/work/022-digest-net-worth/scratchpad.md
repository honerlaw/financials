## Implementation notes 2026-08-24

- `_account_balances` became `_account_rows`, returning an `AccountRow` NamedTuple. The display tuples stayed positional so `account_line(*a)` survives and existing 4-tuple test fixtures keep working; the type/slug/unvested fields the total needs ride on the row, not on the display tuple.
- Introduced `_digest_parts(session, config, today)` as the single impure seam both send paths call, so the scheduled digest and the button cannot drift in what the message contains. `_warn_unmatched` logs; the derivations stay pure.
- **Deviation from the proposal, deliberate:** `account_net_worth` clamps an asset's contribution at zero. `current_balance` and `unvested_value` come from different Plaid endpoints (`accounts/balance/get` vs `investments/holdings/get`), so a stale holdings price can put unvested above the account's own balance and produce a negative asset. This mirrors `sync._refresh_investments`, which clamps the unvested remainder for the same reason ([[021-decision-plaid-vested-value-piggyback-on-sync]]). Not load-bearing enough for a replan — it narrows an edge case within the stated rule rather than changing it.
- Liability type matching lowercases `Account.type` before the set check; Plaid sends lowercase, but the column is a free-form `String(50)`.
- A2P: all three samples regenerated from the new `digest_body`, chosen so that between them they exercise every parenthetical the digest can emit — `(not counted)`, `(unvested excluded)`, `(reconnect needed)`. The campaign description gained a net-worth clause, and section 5's coupling note now names both halves (samples AND description) plus "a new parenthetical note" as a trigger.
